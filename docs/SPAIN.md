CORS ставится **руками в дашборде** — токен намеренно ограничен правами
Object Read & Write на один бакет, поэтому `GetBucketCors` → AccessDenied.
R2 → бакет `photospain` → CORS Policy:

```json
[
  {
    "AllowedOrigins": [
      "https://photospain.co",
      "https://www.photospain.co",
      "http://localhost:3000",
      "http://localhost:3001"
    ],
    "AllowedMethods": ["PUT", "GET", "HEAD"],
    "AllowedHeaders": ["*"],
    "ExposeHeaders": ["ETag"],
    "MaxAgeSeconds": 3000
  }
]
```

Без CORS браузер не зальёт файлы по presigned-ссылкам, то есть **портфолио
фотографа не загрузится** — это обязательный шаг онбординга.

Public Development URL (`r2.dev`) **не включать** — рателимитится.

### Герой главной при пустом ростере

`HeroSingleVariant` строится вокруг живого фотографа и обёрнут в
`{heroPhotographer && …}` — в новой стране запрос пуст, и герой не рендерился
вовсе. `BrandHero` закрывает слот: та же весовая категория, но **никаких
заявлений о ростере** — ни имени, ни рейтинга, ни счётчика. С появлением первого
одобренного фотографа управление возвращается обычному герою.

⚠️ **Без `<h1>`** — H1 живёт в секции ниже. Первая версия повторяла заголовок и
абзац дословно, страница показывала один текст дважды подряд.

### Stripe в текстах

Убирать «подключите Stripe», оставлять «клиент платит через Stripe» — деньги
по-прежнему идут через Stripe и лежат в эскроу. Переопределённые ключи лежат в
РАЗНЫХ неймспейсах, поэтому находились по одному за проход:

`join.gettingStarted.steps.connectStripe.{title,desc}`,
`join.whatYouGet.securePayments.desc`,
`join.howPaymentsWork.{subtitle,steps.clientBooks.desc,steps.youGetPaid.desc}`,
`forPhotographers.whyJoin.benefits.payments.desc`,
`forPhotographers.faq.items[3].a`,
`onboarding.photographer.{connectStripe,connectStripeTip}`,
`supportPage.articles.photographers.getStarted.answer` (шаг 6 списка — нашёлся
последним), `subscriptions.connectWithStripe` (только de).

**Проверка:** страница не должна содержать «Conecte Stripe / Connect Stripe /
Stripe verbinden / Connectez Stripe».

## Интерком отключён

Задеплоено 02.08.2026. Раньше id пространства (`d02q0i7w`) был вшит в
`IntercomWidget.tsx`, поэтому испанский сайт грузил португальский чат, а
серверный синк складывал испанских пользователей в португальский инбокс.

Теперь это поле пака: `country.intercomAppId`. Закрыто с обеих сторон: клиент не
рендерит `<LazyIntercom />` при пустом id (компонента нет даже в RSC-пейлоаде),
сервер выходит раньше, чем дойдёт до API. На отсутствие `INTERCOM_ACCESS_TOKEN`
в `.env` специально не полагались — токен там может появиться случайно.

⚠️ **С 2026-08-11 `intercomAppId` = `null` на ВСЕХ рынках**, включая Португалию:
её пространство выключили осознанно, чат закрывает консьерж. Это намеренное
состояние, а не потерянный конфиг — «восстанавливать» не нужно.

Проверка: `curl -s https://photospain.co/ | grep -ci intercom` → `0`.
